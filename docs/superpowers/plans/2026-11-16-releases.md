# Automatic Releases Implementation Plan

> **For agentic workers:** Use `executing-plans` for native execution in this checkout.

**Goal:** Publish numbered images and GitHub Releases after successful main builds.

**Architecture:** Keep the existing test and multi-architecture build jobs. Add a serialized publication job that reserves a Git tag, promotes the built image, and creates a GitHub Release. A checked-in `VERSION` sets the manually managed major/minor series; CI allocates patch versions.

**Tech Stack:** GitHub Actions, Python standard library, GitHub CLI, Docker Buildx.

**Spec:** The approved release scope in this conversation: start at `0.0.1`, increment patch automatically on successful main publications, retain latest/SHA tags, create matching Git tags and generated release notes, and make reruns safe.

## Global Constraints

- Work natively in the current checkout, as requested. Do not deploy, push, or publish locally.
- Keep pull requests read-only; grant write permissions only to the main publication job.
- Use `uv run --locked` and repository Taskfile commands for validation.
- Keep existing test gates and both Linux architectures.

## Review Focus

- Concurrent publications must not allocate the same version.
- Older commits and reruns must not move latest backwards.
- A publication failure after tag reservation must preserve the version-to-commit mapping.
- A completed release rerun must not replace its image.
- Invalid or regressed manually managed series must fail before mutation.
